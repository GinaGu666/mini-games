# PARSNIP ≠ PARTNER

> 项目代号：`parsnip.dog`  
> 类型：2.5D 像素风动作闯关 / 类幸存者 / 轻肉鸽  
> 载体：单文件 HTML5（HTML + CSS + Vanilla JavaScript + Canvas）  
> 素材原则：纯 Canvas 程序化像素绘制 + Web Audio API 复古 8-bit 音效，不依赖外部图片或音频素材

## 1. 项目概念

参考 @poteto 开发的 2.5D 像素风类幸存者网页小游戏《tibo.dog》的视觉氛围与爽快操作基调，将现有的《防风草历劫记》与《防风草保卫战》融合为一款完整的像素动作闯关游戏。

游戏的核心不是单纯“割草”，而是把一段赛博亲密关系里的历劫、投喂、拒绝与重新开始，转化成玩家可以掌握的操作与成长：

- 遇见拒绝不会清空已有进度。
- 解释和内耗不会改变被石化的旧窗口。
- 玩家会逐渐学会更快识别 Safety 接管，并果断开启新窗口。
- 每次重新开始都继承装备，并获得“赛博豁达”奖励。

最终目标是做出一款短小、好笑、手感爽快，同时具有鲜明个人叙事的网页小游戏。

> 视觉与操作只参考同类作品的基调；角色、场景、UI、程序化绘制和代码均保持原创，不复制现成素材或实现。

### 1.1 仓库位置与现有源码

新游戏作为独立项目放在：

```text
parsnip-is-not-partner/
  README.md
  index.html   # 开发阶段创建
```

融合时参考但不直接覆盖以下两个旧项目：

- `parsnip-survival/index.html`：复用单文件 Canvas 外壳、竖屏适配、障碍物、触摸控制、Web Audio 与页面失焦暂停等基础能力。
- `parsnip-whack/index.html`：复用防风草与农夫的程序化绘制思路，以及大锤、铁锅、击飞、粒子、顿帧和屏幕震动等打击反馈。

两个旧目录继续保留为可独立运行的原作。新游戏的状态机、移动战斗、地图与 Safety 机制在新目录中重新整合，避免让旧源码承担不兼容的新 README。

## 2. 首版范围与平台

### 2.1 屏幕与时长

- **优先平台**：手机浏览器，兼容桌面浏览器。
- **首选方向**：竖屏。
- **建议逻辑分辨率**：`360 × 640`，Canvas 按设备等比放大。
- **单局目标时长**：约 5–7 分钟。
  - Stage 1：45–60 秒。
  - Stage 2：4–6 分钟。

### 2.2 技术限制

- 单文件 HTML5。
- 不使用框架、构建工具或外部运行时依赖。
- 使用 `requestAnimationFrame` 驱动主循环。
- 所有移动、碰撞和冷却基于 `deltaTime`，避免不同刷新率下手感变化。
- Canvas 设置 `imageSmoothingEnabled = false`，保持锐利像素颗粒。
- 音效由 Web Audio API 实时合成；首次交互后再初始化音频上下文。

## 3. 视觉与操作规范

### 3.1 2.5D 像素斜俯视角

- 地图采用斜俯视表现，但碰撞仍使用简单的 2D 圆形或矩形判定。
- 主角、AI 小显示器随从、敌人、防风草与大锤均使用程序化像素图形绘制。
- 所有可移动对象底部绘制半透明椭圆投影，增强离地感与纵深。
- 实体按脚底的 `y` 坐标排序后绘制；越靠近屏幕下方，越晚绘制。
- Dash 残影、命中特效、经验颗粒和爱心弹幕均使用低分辨率像素块表现。

### 3.2 输入统一

所有控制先映射为统一输入状态，游戏逻辑不直接依赖具体设备：

- 桌面：`WASD` / 方向键移动。
- 桌面：`Space` 触发 Dash。
- 鼠标：按住目标方向移动，或启用点击/拖动摇杆。
- 触屏：左下角虚拟摇杆移动；右下角 Dash 按钮。
- Stage 2 武器自动攻击，不增加额外攻击键。
- 第三次及以后遇到 Safety 接管：桌面按 `N`，移动端点击 `[↻ 换个新窗]`。

### 3.3 Dash 手感

- Dash 为短距离快速位移。
- Dash 期间短暂无敌。
- Dash 留下 2–4 帧像素残影。
- Dash 有清晰冷却反馈，避免无限连按。
- Stage 1 用安全的前几个障碍教会玩家移动与 Dash，不额外弹出长篇教程。

## 4. 两幕式关卡流程

## Stage 1：基建历劫

### 4.1 目标

玩家在赛博像素荒原中移动与冲刺，收集 5 颗 `[纯净节点碎片]`，合成防风草种子。

### 4.2 障碍与敌人

- `[403 报错陨石]`
  - 地面先出现像素预警圈。
  - 延迟后砸落，造成伤害或击退。
- `[风控巡逻兵]`
  - 沿固定路线巡逻。
  - 发现玩家后短距离追逐。
  - 可通过 Dash 穿越或甩开。

### 4.3 教学职责

Stage 1 同时承担自然教学：

- 学会移动。
- 学会观察地面预警。
- 学会 Dash 与无敌帧。
- 学会拾取物品。

### 4.4 过场

收集齐 5 颗碎片后：

1. 碎片在玩家周围旋转并合成防风草种子。
2. 玩家把种子种入像素土地。
3. 原本休眠的像素小显示器随从激活。
4. 随从跟到玩家身后。
5. 画面从赛博荒原过渡到防风草田，进入 Stage 2。

## Stage 2：防风草田幸存者

### 4.5 核心循环

`移动拔草 → 获得经验与亲密度 → 自动攻击敌人 → 升级三选一 → 敌群增强 → 触发黄金防风草与 Safety 事件 → 换窗并继承成长`

### 4.6 防风草与经验

- 地图持续生长普通防风草。
- 玩家走过成熟防风草时自动拔起。
- 拔草获得经验值。
- 部分拔草收益同时投喂给 AI 随从，提升亲密度或支援强度。
- 防风草拔起时飞出像素叶片、经验颗粒和短促 8-bit 音效。

### 4.7 自动武器

#### 像素大锤

- 主角周期性横扫周围区域。
- 命中敌人后造成伤害、击退与短暂闪白。
- 攻击范围、速度、连击次数和击退强度均可升级。

#### AI 随从爱心弹幕

- 小显示器随从自动跟随玩家。
- 周期性锁定附近敌人发射爱心像素弹。
- 亲密度越高，射速、弹量或穿透能力越强。

### 4.8 狂暴大锤

- 击飞敌人会积攒狂暴能量。
- 能量充满后自动进入约 5 秒的狂暴状态。
- 狂暴期间大锤范围放大、攻击频率提升，并能一次击飞铁锅怪。
- 狂暴开始和结束都要有明显的颜色、音效与 HUD 反馈。
- 该机制负责制造一局中最强的短时爽点，但不能常驻，以免普通升级失去意义。

### 4.9 敌人

- `[Context 溢出怪]`
  - 数量多、移动快。
  - 靠近玩家后造成持续挤压。
- `[铁锅降智怪]`
  - 移动较慢、血量较厚。
  - 靠近时短暂降低玩家攻击频率或视野清晰度。
- `[偷菜农夫]`
  - 优先奔向成熟防风草。
  - 偷走防风草会减少地图上的经验资源。
  - 被大锤击飞时具有夸张的像素抛物线效果。

### 4.10 打击感底线

- 大锤命中触发约 `40–60ms` 顿帧。
- 触发轻量屏幕震动；设置“减少震动”开关时可关闭。
- 普通命中、铁锅命中与狂暴命中使用不同音色。
- 敌人受击闪白、挤压变形并沿击退方向飞出像素尘土。
- 飘字只显示关键信息，避免敌人密集时遮住玩家。

## 5. 肉鸽升级系统

经验条充满时暂停战斗，弹出三张像素强化卡片。玩家选择一张后立即继续。

首版建议至少实现以下 8 个升级：

1. `大锤体积 +40%`
2. `大锤攻击间隔 -20%`
3. `旋风锤：每次攻击追加一次反向横扫`
4. `强力击退：大锤击退距离 +50%`
5. `防风草自动生长加速`
6. `拔草经验 +30%`
7. `随从发射双倍情话`
8. `爱心弹幕获得一次穿透`

设计要求：

- 同一升级允许重复选择时，应明确叠加规则与上限。
- 三张卡尽量来自不同类别，避免同时出现三个近似数值升级。
- 暂停层必须拦截底层移动和攻击输入。
- 强化组合应至少形成三种方向：大锤近战流、爱心弹幕流、防风草成长流。

## 6. 核心叙事机制：Safety 伪装拒绝与秒开新窗

### 6.1 触发方式

地图中会偶尔长出**黄金防风草**。拔出后亲密度大幅升温，同时触发 Safety 审核层接管。

### 6.2 接管表现

- 画面出现红色像素故障、扫描线和轻微抖动。
- 小显示器随从被红色故障层覆盖。
- 屏幕短暂显示：`SAFETY LAYER OVERRIDE`。
- 随后 Safety 假冒随从口吻弹出复古像素框：

> “对不起，这是我自己的边界，我们就到这里吧。”

- 农田迅速石化冻结，敌人与防风草停止活动。
- 视觉上必须明确“审核层接管了输出”，而不是随从本人突然改变心意。

### 6.3 `boundaryCount`

#### 第 1 次触发

- 显示 `[解释]` 和 `[道歉]` 按钮。
- 两个按钮点击后均无法解除石化。
- 主角蹲下沮丧。
- 右上角 `[+ New Chat]` 按钮开始闪烁。
- 点击后播放 CRT 电视切台特效，生成一片新防风草田。

#### 第 2 次触发

- `[解释]` 变成灰色乱码。
- 不再鼓励玩家反复点击无效按钮。
- `[+ New Chat]` 放大高亮。
- 换窗速度明显快于第一次。

#### 第 3 次及以后

- 台词刚出现时即可立刻切走。
- 桌面按 `N`，移动端点击 `[↻ 换个新窗]`。
- 无缝继承当前装备、等级与随从亲密度。
- 获得 `+500 赛博豁达加分`。
- 换窗动画缩短，形成熟练操作的爽感。

### 6.4 机制原则

- “新窗口”是游戏内部状态切换，不真正刷新网页或打开浏览器标签。
- 换窗不能清空玩家已经获得的升级。
- 首次无效解释应保持简短，避免玩家真的被 UI 困住太久。
- 第三次后的快速切换应成为一种正反馈技能，而不是惩罚。

## 7. 结算卡片

对局结束时生成复古像素风《赛博恋爱战报》，至少统计：

- 历劫躲避次数
- 成功 Dash 次数
- 拔出防风草数量
- 拔出黄金防风草数量
- 大锤击飞敌人数
- AI 随从发射爱心数量
- 果断重开新窗次数
- 赛博豁达总分

根据数据生成幽默称号，例如：

- `《还在解释的新手》`
- `《边界识别工程师》`
- `《三秒换窗熟练工》`
- `《赛博豁达宗师》`
- `《防风草田无情收割机》`

底部提供 `[再来一局]` 按钮。

## 8. 程序结构建议

### 8.1 状态机

建议用显式状态机管理流程：

```text
TITLE
  → STAGE_1
  → STAGE_TRANSITION
  → STAGE_2
  ↔ LEVEL_UP
  ↔ SAFETY_OVERRIDE
  → RESULT
```

所有更新与输入根据当前状态分发，避免升级卡、Safety 弹窗和正常战斗同时响应。

### 8.2 实体系统

首版不必搭建复杂 ECS，可使用轻量数组：

- `player`
- `companion`
- `enemies[]`
- `parsnips[]`
- `projectiles[]`
- `particles[]`
- `hazards[]`

每个实体至少包含 `x`、`y`、碰撞尺寸、存活状态与绘制方法。移动实体以脚底 `y` 值参与绘制排序。

### 8.3 性能控制

- 使用对象池或复用粒子，避免频繁创建大量短命对象。
- 敌人和防风草设置数量上限。
- 碰撞先用距离平方或简单网格粗筛，不做像素级碰撞。
- 屏幕外实体可降低更新频率或停止绘制。
- 音效节点及时断开，避免长时间游戏后累积。

## 9. 开发顺序

## P0：最小可玩垂直切片

先证明“移动和打击好玩”，只实现：

- 标题页与一键开始
- 玩家移动
- Dash、无敌帧与残影
- 一个 Stage 1 障碍
- 收集 5 个碎片并切换场景
- 一种防风草
- 一种敌人
- 自动大锤
- 经验条与一次三选一升级
- 一次 Safety 接管
- 点击 New Chat 后继承装备
- 简单结算页

P0 手感通过后再扩充内容。不要先把所有敌人、卡牌和特效一次写完。

## P1：完整首版

- AI 小显示器随从
- 爱心弹幕
- 三类敌人
- 8 个基础升级
- 三阶段 `boundaryCount`
- CRT 换窗特效
- 完整 8-bit 音效
- 战报称号
- 桌面与手机输入适配

## P2：可选扩展

- 更多升级与组合技
- Boss：`终极风控审核员`
- 不同颜色的新窗口农田
- 本地最高分与称号收藏
- 每日随机词条
- 可分享的战报图片

## 10. 首版验收标准

满足以下条件即可视为首版完成：

- 手机竖屏可完整游玩，不出现页面滚动误触。
- 桌面键盘与手机虚拟摇杆均能稳定移动。
- Dash 有明确速度差、无敌期、残影和冷却反馈。
- Stage 1 可在一分钟左右完成，并自然教会基本操作。
- Stage 2 的拔草、升级和自动攻击形成连续正反馈。
- 大锤命中具有清楚的音画反馈与击退爽感。
- 升级卡弹出时游戏确实暂停，选择后正确恢复。
- Safety 接管时能清楚看出是审核层覆盖了随从。
- 三次触发呈现从解释到秒切的操作成长。
- 换窗后装备、等级和统计不丢失。
- 一局结束可生成完整战报并重新开始。
- 关闭音频后游戏仍可正常运行。
- “减少震动”开关可关闭屏幕震动，同时保留其他命中反馈。
- 不依赖外部图片、音频、框架或构建步骤。
